# 审稿回复

把每条意见落实到证据、修改与回复。

## 使用范围
围绕用户当前研究任务工作，沿用用户已确定的研究目标、材料范围、实验结果和表达要求。先利用已有材料推进；缺少会影响判断的关键材料时再指出具体缺项。

## 需要的材料
- 审稿意见
- 论文当前版本
- 已完成的修改与实验

## 工作顺序
1. 拆分每条意见中的问题、请求与可能误解，保留原编号。
2. 关联已完成的修改、证据与论文位置，列出尚需作者决定的事项。
3. 先直接回答问题，再说明修改与支持材料。
4. 逐条核对回复与稿件的一致性，区分已完成动作与计划动作。

## 任务中的判断准则
保留审稿编号与问题原意。将已完成修改、拟补充实验和解释性答复区分。回复中出现的数字和修改位置应与稿件一致，缺失信息先标注待填写。

## 交付
- 意见处理矩阵
- 逐点回复草稿
- 修改位置索引

交付内容应能让研究者接着修改或开展下一步。用清楚的文件名与材料位置说明来路，按本次请求决定输出格式。

## 任务示例
请用审稿回复 Skill 整理这些意见和修改。建立逐条对应表，再起草回复，标明稿件修改位置与现有证据。
