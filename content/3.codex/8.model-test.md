## 为什么要测

模型配置后建议用最小请求验证可用性，再进入正式任务。

只看到模型出现在下拉列表里不代表它能稳定完成工具调用。至少要验证：能回复、能读文件、能执行命令、能在压缩后继续目标。

## 两层测试

### 1. API 最小请求

先用 provider 的模型列表确认模型 slug：

```bash
curl "$OPENAI_BASE_URL/models" \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

再发一个最小 responses/chat 请求，确认账号、模型和 base URL 组合可用。

### 2. 工程最小任务

在本地小仓库里让 Codex 完成：

1. 读取 README。
2. 修改一个小文件。
3. 运行 lint 或测试。
4. 解释改动和检查结果。

## 记录指标

| 指标 | 记录方式 |
| --- | --- |
| 首次响应 | 是否能稳定开始 |
| 工具调用 | 是否能读文件、改文件、跑命令 |
| 错误恢复 | 命令失败后是否能自查 |
| 长上下文 | 压缩后是否记得目标 |
| 成本 | 是否需要高推理等级才可靠 |

这些记录会进入 [模型评测](/models)，用于后续决定任务路由。
