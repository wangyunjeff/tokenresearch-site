## 基本原则

如果服务需要代理访问，优先确认终端环境变量、IDE 插件代理配置和系统代理是否一致。

同一台机器上最常见的问题不是“没有代理”，而是不同工具读取了不同代理：PowerShell、Git Bash、IDE、桌面端和浏览器的网络路径不一致。

## PowerShell 检查

```powershell
$env:HTTP_PROXY
$env:HTTPS_PROXY
Test-NetConnection api.openai.com -Port 443
```

## Git Bash 检查

```bash
echo "$HTTP_PROXY"
echo "$HTTPS_PROXY"
curl -I https://api.openai.com
```

## Provider 检查

如果使用 OpenAI 兼容服务，先确认 base URL 是否包含 `/v1`，再检查模型列表：

```bash
curl "$OPENAI_BASE_URL/models" \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

## 排错表

| 现象 | 可能原因 |
| --- | --- |
| 浏览器能打开，CLI 不行 | 终端没有继承系统代理 |
| CLI 能用，IDE 不行 | IDE 插件有独立代理配置 |
| `/models` 可用，请求失败 | 模型名、请求格式或账号权限不对 |
| 国内网络偶发失败 | 代理链路不稳定或 DNS 污染 |
