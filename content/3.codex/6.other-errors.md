## 排查入口

先确认 Codex 版本、当前配置文件、模型名、网络连通性和 API 服务返回内容。

## 固定顺序

| 顺序 | 检查项 | 说明 |
| --- | --- | --- |
| 1 | 版本 | `codex --version`，确认是否支持当前功能 |
| 2 | 配置文件 | 检查 `~/.codex/config.toml` 是否有拼写错误 |
| 3 | 模型名 | 模型名要和 provider 的 `/v1/models` 返回一致 |
| 4 | 网络 | 先测基础 HTTPS，再测 API endpoint |
| 5 | 权限 | 文件读写、命令执行和网络权限是否被限制 |
| 6 | 复现 | 用最小任务复现，再回到完整任务 |

## 常见表现

| 现象 | 优先检查 |
| --- | --- |
| 模型不存在 | provider base URL、模型 slug、账号权限 |
| 回复中断 | 网络代理、超时、服务端限流 |
| 工具不能用 | 当前运行环境、权限配置、工作目录 |
| 改错目录 | 启动 Codex 时的 cwd |

## 记录方式

报错不要只截图。建议同时保存命令、完整错误文本、配置片段和发生时间。这样后续切换模型或 provider 时才能判断是配置问题还是服务问题。
