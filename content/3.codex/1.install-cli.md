## 适用场景

CLI 适合做真实仓库里的代码修改、命令执行、测试验证和长任务。它比网页聊天更接近工程现场，因为上下文直接来自当前目录、终端输出和文件树。

## 安装后先检查

按当前平台安装 Codex CLI 后，先确认命令可用：

```bash
codex --version
```

再确认当前 shell 能找到 Node、Git 和包管理器：

```bash
node --version
git --version
pnpm --version
```

## 首次运行

建议先在一个低风险目录运行，观察它是否能正确读取文件、执行命令并说明变更：

```bash
mkdir codex-smoke
cd codex-smoke
codex
```

首次任务不要直接给生产仓库的大范围重构。先让它做一个可验证的小任务，例如创建 README、运行格式化、解释一段脚本。

## 工作目录习惯

| 检查项 | 建议 |
| --- | --- |
| 当前目录 | 进入真实项目根目录后再启动 Codex |
| Git 状态 | 开始前执行 `git status --short` |
| 依赖安装 | 使用项目已有包管理器，不要混用 npm/pnpm/yarn |
| 任务边界 | 一次只给一个清晰目标 |

如果需要使用代理或第三方 OpenAI 兼容服务，先在环境变量或配置文件中完成基础连通性检查，再进入正式任务。
