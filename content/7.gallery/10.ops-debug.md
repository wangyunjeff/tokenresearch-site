## 场景

远程服务器、端口不通、systemd 服务异常、代理配置和 SSH 访问问题。

:skill-result-showcase

## 输入

- 主机地址或 SSH alias。
- 服务名、端口、配置文件路径。
- 期望的最小变更范围。

## 示例输入

```text
这个服务从外网连不上。主机是 server-prod，服务名是 frps，端口是 62441。
请只检查 live state 和必要配置，不要直接重启，最后给我本地和远端验证命令。
```

## 产出

- 当前状态读回。
- 最小修改方案。
- 重启边界和验证命令。

## 示例产出

| 层级 | 检查内容 |
| --- | --- |
| 本地 | DNS、TCP 连通性、客户端错误文本 |
| 远端 | `systemctl status`、监听端口、服务日志 |
| 配置 | 目标配置文件读回、变更前后差异 |
| 边界 | 是否需要重启，谁来重启，重启后怎么验证 |

## 验收清单

- 先记录当前 live state，再提出修改。
- 本地不通和远端未监听要分开判断。
- 配置读回、日志和端口监听三者要能互相解释。
- 用户要求手动重启时，只做配置编辑和读回验证。

## 原则

先验证 live state，再改配置。不要只相信历史文档或记忆。

## 输出标准

结果要分清本地观察和远端观察：本地命令能不能连上、远端服务有没有监听、日志有没有报错、配置是否已经读回。
