## 模型配置

OpenCode 可以按项目或全局方式配置模型。调整后建议执行一次最小任务验证。

## 配置前确认

| 项目 | 检查 |
| --- | --- |
| Provider | Base URL 是否包含正确的 `/v1` 前缀 |
| 模型名 | 是否能在 provider 的模型列表里看到 |
| 鉴权 | API key 是否只放在本机或项目安全位置 |
| 网络 | 终端环境是否能走代理或直连 provider |

## 选择原则

| 任务 | 建议 |
| --- | --- |
| 文档和解释 | 使用速度更快、成本更低的模型 |
| 跨文件代码修改 | 使用推理更强的模型 |
| 视觉检查 | 选择能配合浏览器或截图工具的模型 |
| 长程任务 | 关注上下文保留和压缩稳定性 |

## 验证清单

1. 模型名能被 provider 识别。
2. OpenCode 能读取当前项目文件。
3. 工具调用失败时能展示完整错误。
4. 修改后能运行项目脚本。

把这些结果记录到 [评测记录模板](/models/eval-template)，方便和 Codex、Claude Code 做横向比较。

## 最小验证任务

```text
请只修改一个文档页的一句话，然后运行项目里的最小检查命令。
如果命令失败，先说明失败命令和错误文本，不要扩大修改范围。
```

如果连这个任务都不稳定，不要直接交给它做跨文件重构。
