## 定位

OpenCode 是另一类终端 AI 编码工具。把它放进这个站点，是为了让同一套模型、代理、MCP 和项目规则可以横向比较。

## 安装后检查

安装后先确认命令可用，再配置模型服务：

```bash
opencode --version
opencode --help
```

如果命令不可用，优先检查 Node.js/npm 的全局 bin 路径是否进入 `PATH`。

## 工作目录检查

第一次进入项目时，先让 OpenCode 做只读确认：

```text
请只读当前项目，列出 package.json 脚本、Nuxt 配置文件、content 目录结构，并说明你认为项目根目录在哪里。
```

它的回答必须能对上真实文件。如果它把上级目录、下载目录或临时会话目录当成项目根，先修正启动位置。

## 项目级配置

建议按项目保存 OpenCode 配置，这样不同仓库可以使用不同模型、工具和权限策略。

| 项目 | 建议 |
| --- | --- |
| 模型 | 先配置一个稳定模型，再加入备用模型 |
| 代理 | 与 Codex CLI 使用同一条网络路径 |
| MCP | 只启用当前项目需要的 server |
| 规则 | 与 `AGENTS.md` 保持同一套约束 |

## 最小验证

让 OpenCode 在当前仓库执行一个只读任务，例如解释 README 和列出可用脚本。确认它不会把工作目录识别到上级目录后，再允许它修改文件。
