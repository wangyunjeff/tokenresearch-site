## 基本判断

`low` 和 `medium` 适合短任务，`high` 适合大多数工程任务，`xhigh` 适合需要长时间维持目标、反复检查、处理大量不确定性的任务。

::warning
更高推理等级不等于更高效率。简单任务使用 `xhigh` 通常只会变慢。
::

## 等级边界

| 等级 | 适用任务 | 常见失败 |
| --- | --- | --- |
| low | 短句、翻译、简单解释 | 复杂任务容易漏上下文 |
| medium | 单文件改动、普通 Markdown、轻量脚本 | 多轮错误恢复不稳定 |
| high | 多文件工程、前端截图修复、构建排障 | 长程目标可能仍会遗忘细节 |
| xhigh | 研究评审、自动改进循环、复杂复刻、跨系统排查 | 简单任务成本和耗时过高 |

## 评测任务样例

| 样例 | 推荐判断 |
| --- | --- |
| 翻译一句提示 | low 推荐；medium 可用；high 和 xhigh 过度 |
| 修复一个 lint 错误 | medium 推荐；low 勉强；high 足够；xhigh 过度 |
| 根据截图改移动端布局 | high 推荐；medium 勉强；复杂页面可用 xhigh；low 不建议 |
| 自动改论文两轮 | xhigh 推荐；high 勉强；low 和 medium 不建议 |
| 多服务器部署排障 | high 推荐；高风险时用 xhigh；medium 勉强；low 不建议 |

## 观察指标

| 指标 | 说明 |
| --- | --- |
| 目标保持 | 多轮修改后是否还记得原始边界 |
| 错误恢复 | 工具失败、截图异常或测试失败后能否继续定位 |
| 证据密度 | 结论里是否保留命令、截图、引用或 live state |
| 过度思考 | 简单任务是否被拆得过慢、过重 |

## 小评分表

每次评测按 1 到 5 分记录，避免只写“感觉更好”。

| 等级 | 评分和结论 |
| --- | --- |
| low | 目标保持 1-2；错误恢复 1；证据密度 1-2；成本速度 5。只用于短句和低风险解释 |
| medium | 目标保持 2-3；错误恢复 2；证据密度 2-3；成本速度 4。适合单文件、轻量 Markdown、普通脚本 |
| high | 目标保持 4；错误恢复 4；证据密度 4；成本速度 3。多数工程任务默认选择 |
| xhigh | 目标保持 5；错误恢复 5；证据密度 5；成本速度 1-2。用于长程目标、研究审稿、复杂复刻 |

## 降级和升级规则

| 信号 | 动作 | 原因 |
| --- | --- | --- |
| 修改范围只有一个 Markdown 文件 | 降到 medium | 高推理不会明显提升质量 |
| 连续两次没有修到真实错误 | 升到 high | 需要重建因果链 |
| 需要同时保留截图、代码、命令和用户边界 | 升到 xhigh | 上下文保持比速度更重要 |
| 已进入收尾，只剩格式和链接检查 | 降回 medium | 节省成本和等待时间 |

## 使用建议

`high` 可以作为工程任务默认值；`xhigh` 应保留给长程目标、研究评审、复杂视觉复刻、跨机器排查和需要多轮自检的任务。评测时不要只比较最终文本，要比较是否减少返工和遗漏。
