## 路由原则

不要把所有任务都交给最高推理等级。正确路线是让任务复杂度决定模型和推理强度。

| 任务 | 推荐配置 | 原因 |
| --- | --- | --- |
| 翻译、短文案、轻量说明 | fast / low | 响应快，成本低 |
| 单文件修复、小组件开发 | fast 或 deep / medium | 需要看上下文但不复杂 |
| 多文件重构、构建失败排查 | deep / high | 需要更强的因果链和验证 |
| 长论文、复杂 UI、自动改进循环 | max / xhigh | 需要长程规划和多轮检查 |

## 工具场景表

| 任务 | 路由和验收 |
| --- | --- |
| 修改本站 Markdown 内容 | 工具表面：Codex Desktop / CLI；推理等级：medium；验收：`pnpm lint`、`pnpm check:routes` |
| 复刻或修正页面视觉 | 工具表面：Codex + 浏览器截图；推理等级：high；验收：桌面、移动、暗色截图 |
| OpenCode 项目配置验证 | 工具表面：OpenCode CLI；推理等级：medium；验收：最小任务、模型返回、项目配置读回 |
| Claude Code 插件配置 | 工具表面：Claude Code；推理等级：medium/high；验收：插件上下文、模型配置、一次小修改 |
| 论文分析和改写循环 | 工具表面：Codex + Research Skills；推理等级：xhigh；验收：来源证据、编译或渲染检查 |
| 服务器端口排查 | 工具表面：Codex + SSH/CLI；推理等级：high；验收：服务端状态、日志、客户端探测 |

## 决策表

| 任务类型 | 决策 |
| --- | --- |
| 一句话翻译、报价、短客服回复 | 首选模型路线：Fast；工具表面：Chat / Codex inline；推理等级：low；验证门禁：人工读一遍，确认没有多余事实 |
| Markdown 页面补文案 | 首选模型路线：Fast 或 Deep；工具表面：Codex Desktop；推理等级：medium；验证门禁：`pnpm lint`、相关页面打开无 404 |
| Nuxt 组件和样式修改 | 首选模型路线：Deep；工具表面：Codex Desktop + Playwright；推理等级：high；验证门禁：`pnpm typecheck`、桌面/移动截图 |
| 视觉复刻和移动端 polish | 首选模型路线：Deep，必要时 Max；工具表面：Codex Desktop + 浏览器；推理等级：high / xhigh；验证门禁：多视口截图、Console 无错误 |
| 模型或 Provider 配置验证 | 首选模型路线：Deep；工具表面：Codex CLI / OpenCode / Claude Code；推理等级：high；验证门禁：`/v1/models`、最小任务返回、配置读回 |
| 论文精读、查新和审稿循环 | 首选模型路线：Max；工具表面：Codex + Research Skills；推理等级：xhigh；验证门禁：来源引用、相似工作、局限性和复审记录 |
| 远程服务器排障 | 首选模型路线：Deep；工具表面：Codex + SSH/CLI；推理等级：high；验证门禁：live state、日志、客户端 probe |

## Codex / OpenCode / Claude Code 差异

| 表面 | 适用边界和记录重点 |
| --- | --- |
| Codex Desktop | 更适合：本地仓库改代码、截图验收、长目标持续推进。不适合：只想快速问一句话。记录重点：工作目录、改动文件、命令输出、截图路径 |
| Codex CLI | 更适合：终端优先、配置验证、远程服务器命令。不适合：需要大量 GUI 交互。记录重点：`~/.codex/config.toml`、模型 slug、shell 输出 |
| OpenCode | 更适合：跨 Provider 配置、项目内 AI coding 体验对比。不适合：只验证 Codex 专属功能。记录重点：provider、model、permission、最小修改结果 |
| Claude Code | 更适合：Claude 插件生态、MCP 和 IDE 内体验。不适合：需要复刻 Codex 专属 `/goal` 行为。记录重点：插件配置、MCP 工具、一次真实编辑验收 |

## 切换信号

遇到以下情况，应该升级推理等级：

- 连续两次修改没有触及真实错误点。
- 需要跨多个模块推断数据流。
- 需要同时满足代码、视觉、文案和构建检查。
- 任务目标持续存在，不能只完成局部。

遇到以下情况，应该降级：

- 只是生成短句或摘要。
- 只是修改一个 Markdown 页面。
- 只需要确认一个命令输出。

## 切换后必须验收

升级或降级之后，不要只看回答是否流畅，而要看验收证据是否变好：

| 切换 | 看什么 |
| --- | --- |
| fast 到 deep | 是否改对文件、是否减少返工 |
| deep 到 max | 是否能持续保持目标、是否补齐证据 |
| max 到 deep | 质量是否仍然过关、速度是否明显改善 |
| deep 到 fast | 是否适合短任务、是否没有引入额外假设 |

记录方式见 [评测记录模板](/models/eval-template) 和 [样例评测记录](/models/sample-records)。

## 记录建议

路由记录里必须写清楚“工具表面”。同一个模型在 Codex、OpenCode、Claude Code 或只读聊天里表现可能不同，因为可用工具、上下文注入、权限和系统提示词都不同。
