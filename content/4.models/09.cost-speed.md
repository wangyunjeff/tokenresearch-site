## 评测目标

模型选择不能只看单次价格。真实成本包含等待时间、失败重试、工具调用次数、上下文压缩后返工和人工检查成本。

## 记录维度

| 维度 | 记录方法 | 解释 |
| --- | --- | --- |
| 首次响应 | 从提交任务到第一段有效动作 | 影响交互流畅度 |
| 完成时间 | 从开始到可验收结果 | 影响任务吞吐 |
| 重试次数 | 命令失败、改错文件、返工次数 | 反映隐藏成本 |
| 上下文成本 | 是否需要长上下文或高推理 | 影响预算 |
| 人工检查 | 需要人工补多少验证 | 影响真实效率 |

## 推荐结论格式

```md
任务：
模型：
推理等级：
完成时间：
失败重试：
验证命令：
真实建议：
```

## 成本计算口径

| 项目 | 记录方式 |
| --- | --- |
| 模型调用 | 模型 slug、推理等级、上下文规模 |
| 工具时间 | 等待安装、构建、测试、浏览器截图的时间 |
| 失败返工 | 第几轮失败、失败原因、是否需要人工介入 |
| 人工复查 | 用户需要额外检查的文件、截图、服务状态 |
| 机会成本 | 长任务占用 Agent 时是否阻塞其他任务 |

一个可用的简化公式是：

```text
真实成本 = 模型调用成本 + 工具等待成本 + 失败返工成本 + 人工复查成本
```

## 对比样例

| 场景 | 看似便宜的选择 | 更稳的选择 |
| --- | --- | --- |
| 单句翻译 | fast / low | fast / low |
| 单页 Markdown 补内容 | fast / medium | deep / medium，如果需要读上下文 |
| 前端视觉修复 | fast 多次重试 | deep / high + 截图复查 |
| 论文审稿式修改 | deep 反复补证据 | max / xhigh 一次完整循环 |

## 使用建议

简单任务优先低成本路由，复杂任务优先减少返工。一次用贵模型完成并通过验证，往往比多次便宜模型返工更省。

## 记录口径

记录成本时要把失败重试和人工检查算进去。一个任务如果生成快但没有跑验证，不能直接视为更便宜；它只是把风险转移给了后续人工检查。

## 速度陷阱

| 现象 | 为什么危险 |
| --- | --- |
| 很快给出结论但没有命令 | 可能只是跳过了验证 |
| 很快修改大量文件 | 可能没有建立边界，后续返工更大 |
| 很快通过单一检查 | 可能没有覆盖 typecheck、build、视觉或 live probe |
| 很慢但没有新证据 | 说明高推理没有转化为可复查结果 |
