## 为什么压缩会影响结果

长任务里，模型需要维持目标、文件状态和已经做过的检查。上下文压缩可能丢失一些细节，尤其是目标边界和用户偏好。

## 建议策略

| 场景 | 建议 |
| --- | --- |
| 短任务 | 保持默认 |
| 中等工程任务 | 让 Agent 频繁总结当前文件和验证结果 |
| 长程目标模式 | 把验收标准写在可读文件里 |
| 超长上下文 | 谨慎开启，优先压缩成结构化计划 |

## 压缩前要保存什么

| 信息 | 保存位置 |
| --- | --- |
| 用户硬性要求 | `AGENTS.md`、任务计划或当前页面 |
| 已改文件 | 最终回复、变更摘要或工作日志 |
| 验证结果 | 命令输出摘要、截图路径、route check 结果 |
| 未完成项 | 下一步列表，避免压缩后重复工作 |

## 有害压缩的症状

| 症状 | 说明 | 处理 |
| --- | --- | --- |
| 重复做已完成的检查 | 压缩后丢了命令输出或截图路径 | 先读工作日志或最终摘要 |
| 改到错误页面 | 路由和源文件映射丢失 | 写明 `/codex/model` 对应 `content/3.codex/5.model.md` |
| 忘记用户硬性边界 | 目标、时间、禁止部署等要求丢失 | 放到 `AGENTS.md` 或 goal 摘要 |
| 只记得结论不记得证据 | 没有保存命令、exit code、截图 | 补一段 handoff 摘要 |

## Handoff 摘要字段

长任务压缩前，建议至少保留这些字段：

```md
目标：
必须保留的页面/文件：
已改文件：
已通过检查：
失败过的命令和原因：
截图证据：
仍需验证：
下一步建议：
```

如果任务涉及 Codex 模型、远程压缩或 1M 上下文配置，先把 [Codex 配置/使用](/codex/model) 作为基线页保留下来，再在评测页写自己的实验结论。

## 1M 上下文

1M 上下文不是默认更好。它可能让注意力分散，且成本更高。只有在必须保留大量原始材料时才考虑。

## 评测方法

同一个长任务分别在默认上下文、开启压缩和超长上下文下执行，观察三件事：是否丢失用户边界、是否重复已经完成的工作、是否能继续使用之前的验证证据。只有当超长上下文明显减少返工时，才值得作为默认配置。
