## 为什么需要样例

评测模板只规定字段，样例记录说明怎样把真实任务写成可比较的证据。每条记录都只改变一个变量，并明确验收方式。

## 前端视觉复刻

| 字段 | 记录 |
| --- | --- |
| 任务 | 复刻 Nuxt UI Docs 风格首页和文档页 |
| 输入 | 参考页面、本地截图、移动端 390px 截图 |
| 变量 | Deep 路由 + 浏览器截图 |
| 验收 | `/`、`/codex/model`、`/models`、`/gallery`、`/workflows` 返回 200，桌面/移动/暗色截图无重叠 |
| 结论 | Deep 可作为默认；多轮视觉 polish 时可升到 Max |

## 研究写作

| 字段 | 记录 |
| --- | --- |
| 任务 | 从论文 PDF 提取贡献、实验和可信度判断 |
| 输入 | PDF、arXiv 链接、相关源码或补充材料 |
| 变量 | Max 路由 |
| 验收 | 输出必须包含贡献拆解、方法图、实验表、局限性和复现难点 |
| 结论 | 研究型长文档推荐 Max；摘要和改写可降级 |

## 运维排查

| 字段 | 记录 |
| --- | --- |
| 任务 | 判断远程服务端口是否真实开放 |
| 输入 | 主机、端口、systemd 服务、配置文件和客户端探测 |
| 变量 | Deep 路由 + live probe |
| 验收 | 读回配置、查看监听、查看日志、客户端连通性验证 |
| 结论 | 不接受只看旧文档的结论，必须以 live state 为准 |

## 下一步

把这些记录复制到 [评测记录模板](/models/eval-template)，再按自己的任务替换输入、变量和验收方式。
