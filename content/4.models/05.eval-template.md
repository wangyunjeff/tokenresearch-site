## 模板

```md
---
title: 评测标题
tool: Codex Desktop | Codex CLI | OpenCode | Claude Code
provider: provider-name
model: 模型名
reasoning: low | medium | high | xhigh
date: YYYY-MM-DD
---

## 任务

说明输入、目标和约束。

## 过程

- 工具调用：
- 运行命令：
- 关键错误：
- 修复轮数：
- 开始时间：
- 结束时间：
- 总尝试次数：
- 工作目录：
- 变更文件：

## 结果

- 是否通过 lint：
- 是否通过 typecheck：
- 是否通过 build：
- 是否通过 route check：
- 是否通过视觉检查：
- 关键截图：
- 关键产物：
- 命令输出摘要：
- artifact 路径：
- screenshot 路径：
- 未验证风险：

## 结论

这个模型适合什么，不适合什么。
```

## 对比方法

每次只改变一个变量：模型、推理等级、上下文大小或压缩策略。否则结论很难复用。

## 必须记录的证据

| 任务类型 | 必须证据 |
| --- | --- |
| 代码修改 | lint、typecheck、build 或测试输出 |
| 前端视觉 | 桌面、移动、暗色截图 |
| 文档/论文 | 来源、引用、局限性和可复查文件 |
| 运维排查 | 配置读回、服务状态、日志和客户端探测 |

## 字段说明

| 字段 | 必填原因 |
| --- | --- |
| tool / provider / model | 同一个模型在不同工具表面表现可能不同 |
| reasoning | 用于判断是否该升级或降级推理等级 |
| 开始时间 / 结束时间 | 记录耗时，避免只看最终质量 |
| 总尝试次数 | 反映返工成本 |
| 运行命令 | 让别人能复现验证 |
| artifact 路径 | 指向最终文件、日志、PDF、PPTX 或 build 输出 |
| screenshot 路径 | 前端和文档渲染任务必须留截图证据 |
| 未验证风险 | 防止把“本地通过”误写成“生产可用” |

可以参考 [样例评测记录](/models/sample-records)，不要只写“感觉更好”。

## 命名建议

评测记录标题建议包含任务、模型和日期，例如 `frontend-visual-deep-high-2026-07-09`。如果同一任务比较多个模型，保持输入、命令和截图视口一致。
