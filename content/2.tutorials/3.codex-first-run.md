## 工作目录

先确认 Codex 所在目录是不是项目根目录。Nuxt 项目至少应该能看到：

```text
package.json
nuxt.config.ts
content/
app/
```

如果当前目录只是 Codex 的临时会话容器，先切到真实项目根目录再让 Agent 读代码。第一次运行时可以直接问它列出入口文件、脚本和内容目录，确认它没有在空目录里猜结构。

## 模型和权限

首次运行后，优先检查：

- `/model` 当前选择。
- 是否允许读写项目文件。
- 是否能运行 `pnpm lint`、`pnpm typecheck`、`pnpm build`。
- 是否能访问外网文档或模型服务。

## 最小任务

首次任务建议足够小，便于观察 Agent 是否按项目规则工作：

```text
请只修改一个 Markdown 页面，补一段“输入 / 输出 / 验收方式”，然后运行 lint 和 route check。
```

这个任务能同时验证四件事：是否读了现有文件、是否只改指定范围、是否会运行项目脚本、失败后是否能继续修复。

## 最小验证

先让 Codex 做一个小范围修改，再要求它跑完整验证。不要一开始就给大范围重构任务。

## 常见失败信号

- 不看 `AGENTS.md` 就直接改文件。
- 没确认项目根目录，就开始创建新项目。
- 跑命令失败后只解释原因，没有继续处理。
- 页面任务结束时没有提供本地 URL、截图或路由检查结果。

## 下一步

首次运行通过后，继续看 [Agent 规则](/tutorials/agent-rules) 和 [视觉验收](/tutorials/visual-review)，把验证要求固定下来。
