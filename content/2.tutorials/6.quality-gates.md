## 目标

质量门禁不是为了跑更多命令，而是为了让每次修改都能回答三个问题：代码有没有坏、内容路由能不能访问、用户看到的页面是否正常。

## 推荐顺序

```bash
pnpm lint
pnpm typecheck
pnpm build
pnpm dev --host 127.0.0.1 --port 3000
pnpm check:routes
```

`pnpm check:routes` 需要本地服务已经启动。不要在同一个工作区里同时跑 `typecheck`、`build` 和路由检查，避免 Nuxt Content 的开发库被多个进程同时读写。

## 路由检查

这个站点的 `pnpm check:routes` 会从 `content/` 自动推导 Markdown 页面路由，并额外检查：

- `/raw/codex/model.md`
- `/llms.txt`
- `/llms-full.txt`

其中 `/raw/codex/model.md` 必须和 `content/3.codex/5.model.md` 完全一致，用来保护最初复刻的 Codex 模型页源码。

## 截图检查

核心页面改动后至少看这些页面：

| 页面 | 检查重点 |
| --- | --- |
| `/` | 首页导航、分区卡片、移动端首屏 |
| `/codex/model` | 复刻基线页、左右目录和代码块 |
| `/models` | 评测矩阵和路由说明 |
| `/gallery` | Skill Gallery 卡片密度和换行 |
| `/workflows` | 场景路线卡片和步骤文案 |
| `/skills-mcp` | Skills/MCP 入口和暗色模式 |

## 失败后怎么处理

- lint 失败：先按文件和行号修复，不要扩大重构。
- typecheck 失败：优先确认组件 prop、类型导入和 Nuxt 自动导入。
- build 失败：看第一个实际错误，不要被后续级联日志带偏。
- route check 失败：先确认 dev server 是当前项目，再清理 `.data/content/contents.sqlite` 并重启 dev server。
- 截图异常：保存失败截图和修复后截图，避免只凭记忆判断。
