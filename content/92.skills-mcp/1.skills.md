## Skills

Skills 用于把特定技术栈、工作流或项目约束写成可复用的本地指令。

## 适合写成 Skill 的内容

| 类型 | 示例 |
| --- | --- |
| 技术栈规则 | Nuxt UI、LaTeX、PPTX、PDF、Playwright |
| 项目工作流 | 发布前检查、论文投稿包、实验分析 |
| 外部工具 | Zotero、Chrome DevTools、远程服务器 |
| 验收标准 | 截图检查、编译检查、表格统计 |

## Skill 页面应该写什么

一个好的 Skill 页面要包含：

1. 触发条件：什么时候必须使用。
2. 输入要求：需要哪些文件、URL 或参数。
3. 操作顺序：先读什么，再跑什么。
4. 验收标准：哪些命令或截图必须通过。
5. 失败策略：常见错误怎么降级。

## 最小模板

```md
---
name: my-skill
description: 什么时候必须使用这个 Skill。
---

# My Skill

## 输入

- 需要的文件、URL、参数或上下文。

## 流程

1. 先读取哪些文件或资源。
2. 再运行哪些命令或工具。
3. 最后生成什么结果。

## 验收

- 必须通过的命令、截图、渲染或人工可查证据。

## 失败处理

- 常见错误和降级方案。
```

## 何时升级成 Gallery

当一个 Skill 已经能稳定产出可展示结果时，就应该补 Gallery 页面。Gallery 不写长流程，而是展示示例输入、可交付结果、适用场景和验收方式。

## 和 Gallery 的关系

Skill 是可执行指令，Gallery 是展示它能产出什么结果。Gallery 页面应该面向使用者，讲清楚场景和效果；Skill 文件则面向 Agent，写清楚具体步骤和约束。
