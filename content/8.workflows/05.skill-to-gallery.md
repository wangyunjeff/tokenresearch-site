## 场景

当一个任务已经重复做过多次，并且每次都有稳定输入、工具调用、验收方式和交付物，就应该把它沉淀成 Skill 或 Gallery 页面。

## 推荐路线

1. 从真实任务中提取稳定步骤，而不是凭空写规则。
2. 写清楚触发条件、必须读取的文件、必须运行的验证命令。
3. 在 [Skill Gallery](/gallery) 里补一张卡片，说明输入、输出、场景和边界。
4. 用一个详情页展示结果预览和验收标准。

## 什么时候值得做成 Skill

- 任务会重复出现。
- 失败代价高，需要固定检查顺序。
- 依赖特定工具链或文件格式。
- 需要视觉、编译、渲染或 live state 验证。

## Gallery 页面标准

每个 Gallery 页面至少包含：

- 场景：什么时候调用。
- 输入：需要用户提供什么。
- 产出：最终会得到什么文件或结论。
- 使用边界：什么时候不该调用。
- 验收标准：如何判断结果真的可用。

## 作者检查清单

| 项目 | 要求 |
| --- | --- |
| Frontmatter | `title`、`description`、`navigation.icon` 完整 |
| 路由命名 | 放在 `content/7.gallery/`，使用编号文件名 |
| Preview 卡片 | 在 `SkillGalleryPreview.vue` 增加标题、描述、输入、输出和标签 |
| 结果预览 | 在 `SkillResultShowcase.vue` 增加对应 route 的 showcase 数据 |
| 详情页 | 写清楚示例输入、示例产出、使用边界和验收清单 |
| 验证 | 跑 route check，并至少保存一张详情页截图 |

## 当前项目映射

新增 Skill 展示时，先在 `app/components/content/SkillGalleryPreview.vue` 增加卡片，再在 `content/7.gallery/` 增加编号详情页。如果详情页需要结果预览，同时扩展 `SkillResultShowcase.vue`。

## 完成标准

新增页面不能只出现在侧边栏里。它还应该能从 Gallery 卡片点击进入，并且在详情页里看到“这个 Skill 接收什么输入、会交付什么、用什么证据验收”。
