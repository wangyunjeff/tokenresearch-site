## 场景

同一件事可以用快模型、深推理模型或长上下文模型完成，但成本、速度和稳定性不同。模型路由记录的目的，是让后续选择有证据，而不是只凭感觉。

## 推荐路线

1. 先读 [模型评测总览](/models)，确认任务属于 Fast、Deep 还是 Max。
2. 用 [评测记录模板](/models/eval-template) 记录任务、输入、模型、推理等级和结果。
3. 对前端、研究写作、运维排查等任务分别看对应评测页。
4. 把结论回填到团队的任务路由建议里。

## 记录字段

| 字段 | 写法 |
| --- | --- |
| 任务 | 一句话说明真实任务，不写抽象 benchmark |
| 输入 | 文件、截图、URL、日志或论文 |
| 变量 | 只改一个变量：模型、推理等级、上下文或工具权限 |
| 验收 | 构建、测试、截图、live probe 或引用证据 |
| 结论 | 推荐、可用但偏重、不建议 |

## 失败信号

- 只记录主观感受，没有可重复输入。
- 同时改了模型、提示词和工具权限，无法判断是哪一个变量导致差异。
- 没有验收命令或截图，后续无法复查。

## 输出

一条好的模型路由记录应该能直接变成评测页、FAQ 条目或团队配置建议。
