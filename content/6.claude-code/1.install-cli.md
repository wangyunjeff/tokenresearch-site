## 定位

Claude Code 适合长上下文代码阅读、规划和多文件修改。这个站点把它作为 Codex 的对照工具记录，重点关注模型路由、工具权限和项目规则复用。

## 安装后检查

安装 Claude CLI 后确认账号状态、终端权限和项目目录：

```bash
claude --version
```

再进入真实仓库根目录，确认它读取的是当前项目，而不是临时会话目录。

## 首次只读任务

```text
请只读当前仓库，说明这是 Nuxt、Python 还是其他项目。
列出主要脚本、内容目录、组件目录和你会优先阅读的项目规则文件。
```

如果它不能准确说出 `package.json`、`nuxt.config.ts`、`content/` 和 `app/` 的关系，先不要让它改文件。

## 建议流程

| 阶段 | 动作 |
| --- | --- |
| 首次进入 | 让它总结项目结构和脚本 |
| 修改前 | 明确哪些文件可以改、哪些不能动 |
| 修改后 | 运行 lint、typecheck、build 或对应测试 |
| 结束时 | 要求列出变更文件和未验证风险 |

## 与 Codex 共用的习惯

同一个项目最好维护一份清晰的项目规则文档，避免每个工具都重新学习工程边界。

## 结束时输出

每次 Claude Code 任务结束时都应该交代：

- 改了哪些文件。
- 跑了哪些命令。
- 哪些风险没有验证。
- 是否需要切回 Codex、浏览器或专门 Skill 做后续检查。
